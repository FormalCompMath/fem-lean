# Design RFCs

[中文版本](../zh-CN/rfcs/README.md)

An RFC is required for a mathematical representation or public interface that is
expensive to reverse. Ordinary lemma additions do not need an RFC.

Each RFC should contain:

1. the problem and downstream use cases;
2. constraints and existing ecosystem solutions;
3. genuinely different design options;
4. small Lean interface prototypes where useful;
5. trade-offs and migration consequences;
6. a decision, date, reviewers, and follow-up tasks.

Status values are `Draft`, `Under review`, `Accepted`, `Rejected`, and
`Superseded`. Decisions made in chat are not final until recorded here.
